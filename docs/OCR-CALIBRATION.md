# OCR 标定：从 CER 0.136 到 0.000

> 基准集在 `tools/ocr-bench/`（7 张图 + 参考答案，56 KB），生成脚本 `generate.py`。
> 跑法：`lemma.exe --ocr-bench tools/ocr-bench`

## 为什么要自己造基准集

M4b 接完时，探针那张合成图跑出来是：

```
深度阅读需要把原文和译文放在一起对照      ← 缺句号
Alemmaisthecanolnicalformofaword.      ← 丢空格 + 残字
It keeps every inflection poointing back to one shap
```

肉眼都能看出错，但没有**数字化**的对照就没法判断改动是变好还是变坏。
于是先做了一个 7 张图的基准集，覆盖：深色 UI 白字 / 浅色底黑字、14–28 px 五种字号、
中英文、单行与多行，每张配同名 `.txt` 作为参考答案，用**字符错误率（CER）**度量。

## 三个标定结论

### 1. `unclip_ratio` 从 1.5 提到 3.0（最关键的一处）

DB 输出的概率图是**收缩核**，框比字形小一圈。PaddleOCR 官方的 `unclip_ratio` 是 1.5，
但那是配合它自己的检测尺度用的；在我们这套"长边 960 + 32 对齐"的预处理下明显不够：

| unclip_ratio | 平均 CER |
| --- | --- |
| 0.0 | 0.565 |
| 0.5 | 0.206 |
| 1.0 | 0.179 |
| 1.5（原默认） | 0.136 |
| 2.0 | 0.051 |
| 2.5 | 0.008 |
| **3.0** | **0.005** |
| 4.0 | 0.009（开始把邻行框进来） |

单调改善到 3.0 后回升，是典型的"太小切掉字形上下沿、太大吞进邻行"曲线。
**注意**：只测单行图会一路测到 4.0 都好，必须有多行样本才能看到拐点——这是基准集里那两张
`multi-*` 的唯一作用。

### 2. `REC_MAX_WIDTH` 从 640 提到 960（消除切段残字）

探针阶段测出 640 优于 320 与 1920，于是沿用了 640。但基准集里长行会因此**切成两段**，
而切段会在边界把字切断，产生这类残留：

```
A lemma is the canolnical form of a word.     ← 边界重复了一个 l
It keeps every inflection poointing back …    ← 边界重复了一个 o
```

（去掉重叠能消掉"重复两次"，但剩下被切断的半个字仍会变成错字。）

把上限提到 960 后，屏幕截图里绝大多数行都能**单段识别**，残字消失，基准集从 0.005 变成 **0.000**。

### 3. 行尾丢字不是框的问题

一度怀疑框的横向余量不足（`...one shap` 少了 `e.`），加了 1.5% 横向外扩——结果 CER 从 0.000
**变差**到 0.011，而且没修好。

真实原因：**测试图本身把文字画到了画布外面**。900 px 宽的画布装不下那行 36 pt 的英文，
末尾两个字被裁掉了。换成 1200 px 宽的画布重画，三行全部正确。

教训：用合成图做基准时，先把"源图自身是否完整"排除掉，否则会一直怀疑后处理。

## 最终结果

```
默认参数（unclip=3.0, rec_width=960, det_threshold=0.3, scale=1.0）

dark-16         CER=0.000    287ms（首张含会话创建）
dark-24         CER=0.000     36ms
dark-zh-18      CER=0.000     28ms
dark-zh-28      CER=0.000     32ms
light-14        CER=0.000     31ms
multi-dark-18   CER=0.000     79ms   3 段
multi-dark-24   CER=0.000    118ms   3 段
平均 CER=0.000   平均 87 ms/张
```

长行图（1200×300，三行 36 pt）也全对，耗时 339 ms（冷态，含会话创建）。

## 保留的标定旋钮

都走环境变量，方便换机器/换场景时重跑而不是改代码：

| 变量 | 作用 |
| --- | --- |
| `LEMMA_OCR_UNCLIP` | 覆盖 `unclip_ratio`（默认 3.0） |
| `LEMMA_OCR_THRESHOLD` | 覆盖 det 二值化阈值（默认 0.3） |
| `LEMMA_OCR_REC_WIDTH` | 覆盖 rec 单段宽度上限（默认 960） |
| `LEMMA_OCR_SCALE` | 识别前整体放大倍数（小字号可试 1.5） |
| `LEMMA_OCR_DEBUG` / `LEMMA_OCR_DUMP` | 打印每段宽高比与空格帧数 / 导出模型实际看到的裁剪图 |
| `LEMMA_OCR_REPEAT` | `--ocr` 连跑 N 次，区分冷热态 |

## 还没覆盖的

- **真实截图**：抗锯齿、次像素渲染、非整数缩放（125% / 150%）、浅灰底、彩色背景——都没有。
  基准集是 PIL 渲染的干净图，真实屏幕会更难。
- **旋转与竖排文本**：几何上支持（最小外接矩形 + 透视裁切），但没有样本验证。
- **密集排版**（行距很近、多栏）：unclip=3.0 在这种情况下有吞邻行的风险，需要专门样本调参。
- **UI 字体以外**：只测了微软雅黑，英文实际走的是它的西文部分。
