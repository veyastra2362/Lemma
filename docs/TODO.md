## 会明显影响日常使用

### 1. ✅ 中文分词（M2.1，已完成 2026-11-04）
CC-CEDICT 12.5 万词条 + 逆向最大匹配；中文取词能切词、能查词条、多词时给候选 chips。
实现与取舍见 `.agents/notes/implemented/feature/2026-11-04-chinese-segmentation.md`。

**遗留**：
- 词表加载内存已优化（侧文件方案，已无可测增量，见 #18）；
- 简体优先，繁体词条被丢弃；
- 拼音保留 `ni3 hao3` 原始写法，未转声调符号；
- 不知道"光标落在哪个字"，所以只能给候选列表。
### 2. ✅ 双栏对照窗口（已完成 2026-11-04）
第 4 个窗口（懒创建），块级对齐 + 逐块串行翻译 + 百分比联动滚动；
打开方式三档可配：关闭 / HUD 按钮 / 独立热键（`Alt+R`，可录制）。
实现与取舍见 `.agents/notes/implemented/feature/2026-11-04-dual-column-reader.md`。

**遗留**：双栏里还不能点词下探；滚动是百分比同步，长短块差异大时会漂移。
### 3. 词形反查（went → go）
**现状**：只做后缀回退（复数/过去式去 `s`/`ed`/`ing`）+ `'s`。不规则变化查不到。
**要做的**：给 ECDICT 的 `exchange` 字段建倒排表（`exchange_form → lemma`），导入时顺带写入。
**为什么现在没做**：会让导入体积与耗时上升；当前命中率已够主流阅读。

## 里程碑尚未开工

### 3.5 OCR / TTS 探针已完成（2026-11-04）
实测数据与结论见 [`docs/ONNX-PROBE.md`](ONNX-PROBE.md)。要点：
- OCR mobile det 40 ms + rec 48 ms，RSS 125 MB；**server det 734 ms / 399 MB 且精度无提升**，不要做质量档；
- 精度瓶颈是**框太紧**（外扩 0.3→0.9 倍框高后几乎全对），M4b 重点是 unclip 后处理；
- TTS 空载 **242 MB**、RTF 0.82、会话创建 1.2 s → **进程内常驻不可接受**，要子进程或按需加载；
- TTS 真门槛是**音素化**（input_ids 是音素不是文字），纯 Rust 无成熟方案 → 见 #20。

### 4. 端侧 OCR（M4）
PP-OCRv5 det/rec + 纯 Rust DB 后处理；框选截图 → 双栏对照 → 原图覆盖。
**已知工作量**：后处理（二值化/连通域/unclip/行聚类）占 60%，不是推理。

### 5. 离线朗读（M5）
Kokoro ONNX，流式分句 + 首音延迟 < 400ms + 跟读高亮。

### 6. 标注层 / 原地回填（M6）
默认做标注覆盖层；真替换（`TextRange.SetText`）作为高级选项 + 撤销快照 + 剪贴板回退。
