### 2. ✅ 双栏对照窗口（已完成 · 2026-11-04 补齐图文形态）
**最初的设计意图「图文双栏对照 + 原图译文覆盖层」已落地**：截图 OCR 后点「双栏」，
左原图 + 右译文，可切「并排 / 覆盖」两种形态；覆盖模式把译文直接贴到原图对应文本框上。
取舍见 `.agents/notes/implemented/feature/2026-11-04-reader-image-dual-column.md`。

实现与取舍见 `.agents/notes/implemented/feature/2026-11-04-dual-column-reader.md`。

**遗留**：双栏里还不能点词下探；滚动是百分比同步，长短块差异大时会漂移。
### 3. 词形反查（went → go）
**现状**：只做后缀回退（复数/过去式去 `s`/`ed`/`ing`）+ `'s`。不规则变化查不到。
**要做的**：给 ECDICT 的 `exchange` 字段建倒排表（`exchange_form → lemma`），导入时顺带写入。
**为什么现在没做**：会让导入体积与耗时上升；当前命中率已够主流阅读。

## 里程碑尚未开工

### 3.5 OCR / TTS 探针已完成（2026-11-04）
实测数据与结论见 [`docs/ONNX-PROBE.md`](ONNX-PROBE.md)。要点：
- OCR mobile det 40 ms + rec 48 ms，RSS 125 MB；**server det 734 ms / 399 MB 且精度无提升**，不要做质量档；
- 精度瓶颈是**框太紧**（外扩 0.3→0.9 倍框高后几乎全对），M4b 重点是 unclip 后处理；
- TTS 空载 **242 MB**、RTF 0.82、会话创建 1.2 s → **进程内常驻不可接受**，要子进程或按需加载；
- TTS 真门槛是**音素化**（input_ids 是音素不是文字），纯 Rust 无成熟方案 → 见 #20。

+ rec（长行切段 + CTC 解码）；热态 156–163 ms；`lemma.exe --ocr <image>` 可无头验证。

### 5. 离线朗读（M5）
**M5a 已完成（2026-11-04）**：`core/tts/` 落地——纯 Rust 音素化（拼音→注音）、
Kokoro 中文模型推理、WAV 输出；`lemma.exe --tts <text> <out.wav>` 可无头验证。
RTF 实测 **1.07–1.32×**（合成慢于实时），会话创建 1.2 s。

**M5b 第一批已完成（2026-11-04）**：HUD 与双栏的朗读入口、`speak_text` 命令（async）、
GDI 无关的播放（`PlaySound`）、语速设置、"合成完卸模型"（实测 332→71 MB）。
`lemma.exe --tts` 与 `LEMMA_SPEAK_SMOKE` 可无头验证。

**剩余（M5b）**：

- ~~进程隔离~~（已完成，见 #21）
