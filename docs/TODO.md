# 待做清单

> 按「影响使用价值」排序，不按技术难度。已完成项见 [README 的路线图](../README.md#路线图)。
> 每项都注明了为什么现在没做——避免下次重新论证一遍。

## 会明显影响日常使用

### 1. 中文分词（M2.1）
**现状**：UIA 的 `TextUnit_Word` 对中文只在标点/空白处断词，实测会返回单字（`第`）或整段（`当前进度：`）。
词库是英→中，所以**中文取词基本只能得到"未收录"**。

**要做的**：接一个中文词典（如 CC-CEDICT / jieba 词表），实现最大匹配；把 `core::text::trim_word` 扩成
`segment(text) -> Vec<Token>`，让中文也能点词下探。

**为什么现在没做**：需要额外词库与分词词典，属于独立工作量；M3 先把"英文长句翻译"这条主路打通。

### 2. 翻译的双栏对照窗口（M3 剩余）
**现状**：句子/段落选中后在 HUD 里给译文（单栏）。
**要做的**：独立阅读窗口，左原文右译文，段落级联动滚动；需要第 4 个窗口 + 段落对齐算法。
**为什么现在没做**：先把翻译链路跑通；双栏是体验增强，不影响"能不能用"。

### 3. 词形反查（went → go）
**现状**：只做后缀回退（复数/过去式去 `s`/`ed`/`ing`）+ `'s`。不规则变化查不到。
**要做的**：给 ECDICT 的 `exchange` 字段建倒排表（`exchange_form → lemma`），导入时顺带写入。
**为什么现在没做**：会让导入体积与耗时上升；当前命中率已够主流阅读。

## 里程碑尚未开工

### 4. 端侧 OCR（M4）
PP-OCRv5 det/rec + 纯 Rust DB 后处理；框选截图 → 双栏对照 → 原图覆盖。
**已知工作量**：后处理（二值化/连通域/unclip/行聚类）占 60%，不是推理。

### 5. 离线朗读（M5）
Kokoro ONNX，流式分句 + 首音延迟 < 400ms + 跟读高亮。

### 6. 标注层 / 原地回填（M6）
默认做标注覆盖层；真替换（`TextRange.SetText`）作为高级选项 + 撤销快照 + 剪贴板回退。
