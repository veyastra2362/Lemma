# Agent Note: UI v2 —— 石墨 + 单一强调色的桌面工具风格

Status: proposed

## Problem

现在的界面是一版版"能用就行"堆出来的：

- 令牌只有 5 个（`--hud-surface/border/text/muted/accent`），色相是冷色（`oklch(... 265)`），
  和"阅读工具"应有的暖调不搭；
- 正文字号在 10–13px 之间混用，10px 的说明文字在 125% 缩放下几乎读不清；
- 组件各窗口各写一套：设置页是一整页单选卡堆叠，浮层顶部放的是开发信息
  （"高频深度阅读辅助""热键 → 首帧 20.6ms"）；
- 没有统一的圆角/间距节奏，也没有动效规范。

`docs/ui-redesign-prompts.md` 给出了明确方向：**quiet editorial desktop utility**，
石墨 + 暖白 + **一个低饱和强调色**，禁止蓝紫渐变、青色霓虹、玻璃拟态、发光边框。

## Proposal

### 令牌层（阶段 0，已完成）

`src/styles.css` 重定义为石墨三层 + 暖白文字 + 陶土强调：

| 用途 | 令牌 | 值 |
| --- | --- | --- |
| 画布 | `--hud-canvas` | `#171716` |
| 面板 | `--hud-surface` | `#242321` |
| 抬起 | `--hud-raised` | `#2d2b28` |
| 边框 / 弱边框 | `--hud-border` / `--hud-border-soft` | `#46423d` / `#35322e` |
| 正文 / 次要 / 最弱 | `--hud-text` / `--hud-muted` / `--hud-faint` | `#eeeae1` / `#aaa49a` / `#777168` |
| 强调 | `--hud-accent` / `--hud-accent-soft` | `#bd7454` / `#3c2d27`（橄榄：`#98a67d` / `#2e3327`） |
| 语义 | `--hud-ok` / `--hud-warn` / `--hud-err` | `#8c9c7d` / `#c4a36b` / `#b86b67` |
| 圆角 | `--hud-r-win` / `--hud-r-panel` / `--hud-r-ctl` | 12 / 8 / 6 |

**命名仍是 `--hud-*`**：它是既有组件的色彩接口，改名会把所有窗口的样式一起拖进来，
而这次是"一个窗口一个窗口地改"，接口名不变才能让每一步单独构建、单独回滚。

强调色做成**运行时可切换**（默认陶土，可换橄榄）：`<html data-accent="clay|olive">`，
设置里新增 `accent` 字段；四个窗口是独立 webview，所以每个窗口在 `App.tsx` 里
自己应用一次，并监听 Rust 侧已有的 `settings://changed` 广播。

### 分阶段实施（每个阶段单独构建 + 单独提交）

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| 0 ✅ | 令牌层 + 配色开关 + 全局应用链路 | 浮层变成暖石墨、强调色为陶土；设置里能切换且立即生效 |
| 0.5 ✅ | **修直角阴影**：面板四周留 8px 透明边距（`--hud-gutter`），`HUD_WIDTH` 420→436、`HUD_MIN_HEIGHT` 132→148 | 放大四角截图：圆角是圆的，阴影在窗口内淡出 |
| 1 ✅ | **取词浮层**（ShellView）：克制标题栏 + 下探路径 + 三种卡片 + 键帽式底部提示 | 句子卡截图通过；词条卡与 OCR 卡逻辑同构 |
| 2 ✅ | **设置**（SettingsView）：左导航 10 分类 + 右内容，一次只显示一类 | 呼出方式 / 翻译两屏截图通过；结构同构，其余分类共用同一套行组件 |
| 3 ✅ | **截图对照**（ReaderView）：编号对齐 + 悬停同步高亮 + 覆盖气泡 + 单条词条 | 并排/覆盖两态截图通过（真实 OCR 内容） |
| 4 | **框选层**（RegionSelectView）：45% 遮罩 + 陶土选区 + 角标 + 尺寸 + 识别中态 | 拖拽/识别中两态截图 |
| 5 | 动效收尾 + 全量验收（`docs/ACCEPTANCE.md`） | 逐项点击走查 |

动效规范：**只过渡颜色与描边，120ms `ease-out`**；气泡 120ms 淡入；
不做缩放进入、不做回弹、不做循环装饰；全部遵守 `prefers-reduced-motion`。

## Alternatives considered

- **保持冷色 oklch，只调字号**：改动最小。否决原因：用户要的是"整体重做"，
  而冷色相是这套 UI 最像"AI 产品"的地方；换色只是改 5 个变量，收益最高。
- **引入 Tailwind 主题（`@theme`）注册颜色类**：更"正规"。否决原因：现有组件大量使用
  `text-[var(--hud-muted)]` 这类任意值，注册主题要同时改组件；而令牌变量已经够用。
- **改名成 `--lm-*` 与新设计对齐**：命名更干净。否决原因：会让每个阶段的 diff 都混入
  纯改名噪声，看不出真实改动；等全部窗口改完再考虑统一改名。
- **配色做成"主题包"（多套完整主题）**：扩展性最好。否决原因：产品只有一个使用场景，
  两套强调色足够；主题包会引入"某套主题没测过"的状态。

## Acceptance criteria

- 四个窗口全部使用新令牌，无硬编码颜色（除设计稿里明确标注的色板）；
- 正文字号 ≥ 12.5px，元信息 ≥ 11px；
- 没有任何渐变、`backdrop-filter`、发光阴影；
- 圆角只有 12 / 8 / 6 三档；
- 设置里切换强调色，浮层与对照窗口**立即**跟随（不需要重启）。

## Risks

- 逐窗口改会有一段时间"新令牌 + 旧布局"并存，视觉上不一致 —— 这是分阶段实施必然的中间态，
  用阶段提交记录每一步。
- `--hud-accent` 在组件里常与透明度修饰符组合（`/15`、`/35`），改成实色后这些组合的观感会变，
  需要在每个窗口的阶段里单独看一遍。
- 尺寸相关的令牌（`--hud-r-*`）只有在组件真的用了之后才有意义，过早定义可能被误用。
