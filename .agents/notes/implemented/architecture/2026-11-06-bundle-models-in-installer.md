# 模型权重随安装包分发

- 日期：2026-11-06
- 状态：implemented
- 取代：早先「OCR/TTS 权重既不进仓库也不进安装包」的口头约定（用户明确要求改）

## 背景

此前的分发方式是「安装包 6 MB + 用户自己往数据目录放模型」。验证全新用户路径时确认了代价：
装完打开设置，OCR / 朗读 / 汉语词典三项全是「未安装」，用户得自己去下载 140 MB 权重
并放进 `%APPDATA%\dev.lunar.lemma\`。用户要求把 OCR 与朗读模型**内置**。

## 决定

`bundle.resources` 带 `models/ocr/*` 与 `models/tts/*`，首次启动把缺失的文件复制到应用数据目录。

- 权重仍**不进仓库**：`.gitignore` 增加 `src-tauri/models/`（整目录，不只是 `*.onnx`——
  `cmudict.dict` / `zf_001.bin` / `ppocr_keys_v1.txt` / `tokenizer.json` 也会被提交）。
  也就是说仓库保持干净，但本机构建需要有这批文件；移植机器时先补齐 `src-tauri/models/`。
- 只在**文件不存在时**复制：用户可以自己替换或删掉模型，安装包不会覆盖。
- 复制发生在 `setup` 最前（`core::bundle::seed_models`），在 `models_ready()` 判断之前。

## 代价（实测）

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| NSIS 安装包 | 6.19 MB | **103.90 MiB** |
| 全新用户首次启动（含复制 140 MB） | 1835 ms | **1173 ms**（本来就要初始化 WebView2） |
| 磁盘占用 | 数据目录 140 MB | 安装目录 140 MB + 数据目录 140 MB（复制一份） |

## 放弃的方案

**直接从安装目录读模型**（不复制）。它省掉磁盘上的一份副本，但要改 `core::ocr` / `core::tts`
里所有「数据目录 + 固定文件名」的查找逻辑，或者引入一个运行期可覆盖的全局路径；
两条路都会让"设置页显示的是数据目录、实际读的是安装目录"这种错位更难排查。
机构成本换 140 MB 磁盘，不值得。

**模型单独做下载器**（首次启动引导下载）。安装包能保持 6 MB，但需要托管、断点续传、
校验与失败恢复——为一个桌面阅读工具引入 CDN 依赖，收益不成比例。

## 后果与遗留

- 安装包体积从「随便发」变成「100 MB 级」，分发渠道（如 GitHub Release）要确认能接受。
- **中文朗读依赖词库**：拼音来自 CC-CEDICT，所以全新用户（没有 `dict.redb`）点朗读会报
  `词库不存在`，英文朗读则可正常（`tts english dict loaded`）。这是内置模型之后仍然存在的
  「装完还不完整」的空档，是否把 ECDICT（MIT）/ CC-CEDICT（CC-BY-SA）也打进安装包待定。
- 汉语词典（chinese-xinhua）**不内置**：数据版权归属不明确，只在设置里给推荐与导入命令。
