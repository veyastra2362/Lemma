# Agent Note: 光标远离自动收起浮层

Status: implemented

## 问题

浮层（HUD）挡住了原文，看完要按 Esc 或点 ✕ 才消失；用户希望像 Telegram 那样——
**鼠标移开就自己关**。

## 决定

光标离浮层超过 **260 物理像素**（125% 缩放下约 200 逻辑像素）并持续约 300ms 就收起。
默认开启；开启时**隐藏 ✕ 按钮**（移开即可，按钮显得多余）。

实现位置：`core/shell.rs` 的 `spawn_proximity_watch`，由 `present()` 在显示浮层后起一个
线程轮询全局光标位置（100ms 一次），判定规则刻意保守：

1. **弹出后宽限 700ms**——此时鼠标通常正停在刚选中的词上，立刻判定会让浮层秒关；
2. **必须先靠近过再离开**（`was_near`）——从托盘打开的浮层，鼠标本来就在远处，
   不能因此立刻关掉；
3. **连续 3 次（约 300ms）判定为远**才收起——避免手抖或贴着边缘移动时误关；
4. 每次 `present()` 递增代数计数，旧的看门狗看到代数变化就退出，不会多个线程抢同一个浮层。

## 备选方案

**前端监听 `mouseleave`**。只对"移出窗口"有效，浮层周围没有透明边距，
鼠标移出即触发，太敏感；而且窗口失焦时前端可能收不到事件。

**用 `WM_MOUSELEAVE` + 定时器在平台层做**。等价于现在的轮询，但要多写一套消息循环，
收益为零——100ms 轮询一个 `GetCursorPos` 的开销测不出来。

**距离做成可调**（设置里给滑杆）。目前固定 260px 覆盖了"移到旁边继续读"与"移开走人"两种情况；
等有人抱怨再给滑杆。

## 后果

- 开销：浮层可见时多一个 100ms 的轮询线程，`GetCursorPos` 是纯用户态查询，可忽略。
- 关闭此功能（设置 → 界面 → 光标移开自动关闭）后 ✕ 按钮恢复显示，行为回到原来的手动关闭。
- 与 Esc 并存：Esc 依然立即关闭，不受该设置影响。
