# Agent Note: 双栏收窄为「截图对照」，删掉取词双栏与双栏热键

Status: implemented

## Problem

双栏（并排对照窗口）原来对**任何**取词结果都开：

- 选中一个词/一句话 → HUD 已经并排显示「原文 + 译文」；
- 再点「双栏」→ 又开一个窗口，把同样的原文和译文左右摆一遍。

用户的原话：**「如果是选词用双栏的话，感觉很鸡肋。不如双栏就给 OCR 的时候用。」**

这个判断是对的：双栏的价值在**一屏成段文字 + 逐块对照**，而单词/单句的信息量小到一张卡片就装得下，
再开窗口只是把同一份信息重复摆放，还多一次焦点切换与一次窗口创建。

另外顺带查出一个更糟的问题：设置里「用热键打开」这一档是**真的注册了热键**的，
按下后做的事是"取词 → 开一个纯文本双栏"——正是上面那条鸡肋路径，而且它绕过了 HUD。

## Decision

**双栏只对截图识别结果开放。**

1. `ShellView` 给卡片加 `screenshot` 布尔（来自 `capture.tier === "ocr"`），只有它为真时渲染「双栏」按钮；
   不拿 `source` 那个展示字符串做判断（文案一改就失效）。
2. `commands::open_reader` 增加后端守卫：当前 reader payload **没有图**就报错
   "双栏只用来看截图对照"，不再把纯文本塞进 payload。
3. `trigger.rs` **删除双栏热键注册**；`reader_hotkey` 字段保留只为兼容旧配置（不再注册任何键）。
4. 设置项从三档（关闭 / 从 HUD 打开 / 用热键打开）收成两档（关闭 / 在截图上显示「双栏」入口）；
   存量配置里是 `hotkey` 的一律按"打开"处理。

## Alternatives considered

- **保留取词双栏，但默认关掉**：改动最小。否决原因：功能还在，就还会有人点开并再次觉得鸡肋；
  而且它占着一个热键、一段设置说明、一条 `text_only` payload 路径——维护成本不会因为默认关而消失。
- **取词时自动判断"值不值得开双栏"**（比如超过 N 字才显示入口）：看起来聪明。否决原因：
  阈值只能靠猜，用户也无法预期按钮何时出现；按**来源**判断（截图/不是截图）语义清楚得多。
- **让「双栏」变成主窗口、HUD 只做提示**：更彻底。否决原因：HUD 的毫秒级呼出是这个项目的核心，
  把它降级成提示会毁掉"不离开当前页面"的定位。
- **保留双栏热键，但改成打开"最近一次截图"**：能保住热键的便利。否决原因：
  需要额外维护"最近一次截图 payload"的生命周期与失效规则，收益只是省一次点击；
  真需要时从 HUD 上点一下也就一步。

## Consequences

- 收益：少一个会让人困惑的入口；设置项从三档降到两档；`text_only` 双栏这条路径不再被用户触发
  （代码仍在，供内部冒烟使用）。
- 代价 1：**纯文本长文没有对照阅读入口了**。若以后要（比如整段选中一篇英文），
  应该做成"截图之外的第二种来源"，而不是把按钮重新挂回所有卡片。
- 代价 2：`reader_hotkey` 变成**死字段**。它还在 `settings.json` 里、还在设置变更检测里，
  但不再注册。这是为兼容旧配置付的账，删字段会让存量配置反序列化失败。
- 代价 3：`open_reader` 现在会对纯文本报错。若将来有别的调用方（冒烟脚本）传纯文本，会拿到 error。
- 教训：**功能"能挂上去"和"挂上去有意义"是两件事。** 双栏挂给所有卡片在实现上一行代码，
  但它只在"一屏成段文字"这个场景里成立。

## Testing

真机点击走查（模拟鼠标键盘，非改代码）：

- 文本卡片（Firefox 选区）→ HUD 按钮只有「朗读」，**没有「双栏」**（截图确认）。
- 截图识别（`Alt+S` 拖框）→ HUD 出现「朗读 | 双栏」，点「双栏」→
  `window created reader` → `reader opened` → 逐块翻译。
- 期间日志出现 `tts worker reaped (idle)`，顺带确认空闲回收生效。
