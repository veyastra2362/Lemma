# Agent Note: 双栏底部去掉下探栈；快捷键提示统一受 `showHints` 控制

Status: implemented

## Problem

两件相关的小事，都是"把 HUD 的形态照搬到别的窗口"造成的：

1. **双栏底部的词条面板带着下探栈和面包屑**（`A › B › C`）。用户的反馈：
   "下面这个层级好像有点问题，它应该是没有层级的吧。"
   他判断对了：双栏底部只是**随手查一下**的附注面板，点第二个词就该把内容换掉，
   而不是压一层新层级。层级只在 HUD 的卡片栈里成立——那里每一层是用户探索的一步，
   面包屑用来回退。
2. **「Esc 逐层退出」这类提示不受设置控制**。设置里早就有「显示快捷键提示」（`show_hints`），
   但只有 HUD 底部那排接了这个开关；双栏底部、框选层的提示是写死的。
   **相当于设置里摆了一个只对三分之一界面生效的开关。**

## Decision

### 1. 双栏底部：栈 → 单条

`drill: Drill[]` 换成 `lookup: Drill | null`：

- 点词 → 直接替换内容（`setLookup`），不再 push；
- `Esc` → 有词条就关词条，没有就关窗口；
- 面板右上角给一个显式的「关闭」按钮（不依赖用户记快捷键）；
- 词条里的词仍然可点，点了就换成那个词。

`MAX_DRILL` 与面包屑一并删除。

### 2. 快捷键提示统一走 `showHints`

- 双栏底部：`showHints` 为真才显示 `Esc 关闭词条 / 关闭窗口`；
- 框选层：拖拽说明**始终显示**（不显示用户就不知道要做什么），只有「Esc 或右键取消」这半句受开关控制；
- HUD 底部：本来就接了，保持不变。
- 设置里的说明文案改成"各处（HUD 底部、双栏词条、框选层）"。

## Alternatives considered

- **保留栈但隐藏面包屑**：改动更小。否决原因：栈本身也没用——用户看不到栈，也无法预期
  "再点一个词会不会压层"，行为仍然不透明。**看不见的复杂度仍然是复杂度。**
- **保留栈，把面包屑做成"返回上一层"的唯一入口**：能保住"连查几个词再退回"的能力。否决原因：
  在附注面板里连查几个词是极低频操作，为它保留一套栈 + 面包屑 + Esc 语义不划算；
  真要连查，HUD 的卡片栈就是干这个的。
- **`showHints` 关掉时框选层也不显示拖拽说明**：与"关掉提示"字面一致。否决原因：
  拖拽说明是**操作指引**不是快捷键提示；关掉后框选层会变成一块没有任何说明的暗色遮罩，
  用户不知道该干什么。
- **把 `showHints` 拆成多个更细的开关**（HUD / 双栏 / 框选各一个）：更"精确"。否决原因：
  用户要的是"界面干净点"，不是要配置三处；一个总开关符合直觉。

## Consequences

- 收益：双栏底部变成一块干净的单条面板；`showHints` 从"只对 HUD 生效"变成全局生效。
- 代价 1：双栏里**不能再连查多个词再逐层退回**。想连查就用 HUD（那里的栈是完整能力）。
- 代价 2：`readerEscHint` 的文案从"Esc 逐层退出"改成"Esc 关闭词条 / 关闭窗口"——
  语义变了，旧的翻译键值同步更新。
- 代价 3：框选层的文案被拆成两段拼接（`regionHint` + `regionHintCancel`），
  翻译时要保证两段拼起来读得通顺。
- 教训：**开关要么全局生效，要么别放在"全局设置"的位置上。** 这次的 `show_hints`
  显示在设置页里，看起来像全局开关，实际只影响 HUD。

## Testing

真机点击走查：

- 双栏里点左栏的词 → 底部出现单条词条 `is /ɪz/  be的现在式第三人称 …`，**没有面包屑**，
  右上角是「关闭」；此时**没有 Esc 提示**——因为该机器 `showHints` 为 `false`，说明开关生效。
- 头部两个朗读按钮（原文/译文）同时可见，与上一轮改动一致。
